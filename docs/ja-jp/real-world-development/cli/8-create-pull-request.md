フィルター機能の実装、指示の更新、スキルの更新、品質保証 (QA) プロファイル、テストを1つのブランチに保存しました。すべてをまとめてレビューし、プルリクエストを作成します。星評価のプルリクエスト (PR) は自分でマージしましたが、今回は **Agent Merge** にプロセスを任せます。

> [!NOTE]
> 通常は、機能、指示の更新、スキルの更新、QA エージェントを複数の PR に分けます。このワークショップでは手順を簡潔にするため、フィルター機能と品質ワークフローの作業を1つの会話とブランチにまとめ、この PR に含めます。

このレッスンでは、次の操作を行います。

- Agent Merge とは何か、マージまでのワークフローを自動化する方法を学びます。
- 機能の全変更と検証の根拠を確認します。
- フィルター機能の PR を作成します。
- レビュー後にのみ Agent Merge を有効にし、PR がマージされたことを確認します。

## シナリオ

フィルター機能のワークフローを通じて、Copilot を使って機能を計画、実装、検証してきました。Tailspin Toys では、マージの承認は開発者が管理したまま、残りの PR 作業を自動化したいと考えています。

## Agent Merge について

**Agent Merge** は、プルリクエストをマージするために必要な残りの作業を自動化します。有効にすると、Copilot は PR をブロックしている問題に対応します。CI チェックの失敗を修正し、レビューコメントに対応し、必要に応じてリベースします。その後、リポジトリで許可されていれば、GitHub の自動マージを有効にします。

これまでは自分で **Merge pull request** を選択していました。Agent Merge にその役割を任せることもできます。Agent Merge を有効にする前に、作業をレビューし、マージ可能な状態であることを確認してください。

## Agent Merge で PR を管理する

コードの作成がすべて終わったら、全体をレビューし、PR を作成して、残りのプロセスを Agent Merge に任せましょう。

1. Codespace に戻ります。
2. `/agent` を入力してエージェントのダイアログを開きます。
3. 一覧から **Default** を選択し、<kbd>Enter</kbd> を押します。
4. `/pr create` コマンドを使って新しい PR を作成します。
5. `/pr agentmerge` コマンドを使って Agent Merge を有効にします。
6. Copilot は PR の継続的インテグレーションプロセスを監視します。すべて成功したら、マージを実行します。
7. Copilot から「PR #14 was squash-merged successfully.」のようなメッセージが表示されたことを確認します。

> [!IMPORTANT]
> Agent Merge は、必須の承認、ブランチ保護、マージキュー、リポジトリの設定、権限の不足を回避しません。ブロックされた場合は報告された理由を確認し、リポジトリで許可される場合は、レビュー済みの PR を手動でマージしてください。
