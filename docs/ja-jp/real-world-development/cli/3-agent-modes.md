プロジェクトに小さな機能を追加しました。しかし、より大規模な変更には、さらに堅牢なプロセスが必要です。GitHub Copilot CLI は組織の既存のフローに沿って作業できます。つまり、適切なものを適切な方法で構築できます。このレッスンから数回にわたり、一般的なエージェント主導の開発プロセスを実践します。Issue を使って新機能を生成し、コードが有効で、機能が期待どおりに動作することを確認し、最終的にプロジェクトにマージします。

> [!NOTE]
> 機能のワークフローを進める間は、同じ会話とブランチを使用します。通常は作業対象のファイル種類ごとに異なるブランチや PR を使用しますが、ここでは中心となる概念に集中できるよう手順を簡略化します。

このレッスンでは、次の操作を行います。

- GitHub Issue から新しい Copilot の会話を開始します。
- Plan モードで要件を定義します。
- Autopilot モードで新しい機能を実装します。
- コードをレビューします。
- 転送されたブラウザーで機能を手動で検証します。

この機能の作業を続けながら、リポジトリの指示を更新し、既存の `quality-checks` スキルをカスタマイズし、MCP による検証を追加して QA エージェントを作成し、機能の PR を開きます。

## シナリオ

Tailspin Toys のカタログが充実し、訪問者がカテゴリと publisher でゲームを絞り込める機能が必要になりました。バックログの Issue に機能は記載されていますが、カテゴリを組み合わせる方法などはコーディング前に合意する必要があります。Plan モードでこれらの決定を行い、範囲を明確に定めた実装を Autopilot で実行するよう承認します。

## 背景

AI コーディングエージェントを開発フローに導入しても、基本は変わりません。むしろ、さらに重要になります。多くの開発者は、次のようなフローに従います。

1. 必要な作業の内容が記載された Issue を開きます。
2. 構築する内容の計画を作成します。
3. コードを構築してレビューします。
4. テストを実行してコードを検証します。
5. 新機能を手動で検証します。
6. プルリクエスト (PR) を作成します。
7. コードレビューと継続的インテグレーションのプロセスが成功したら、コードをマージします。

> [!NOTE]
> 正確な手順はチームや組織によって異なりますが、多くの場合は上記の流れを変形したものです。

この標準的なアプローチを守ることで、AI が生成したコードが定められた要件を満たし、人間が作成したコードと同じレビューのプロセスを通るようにできます。

## 会話モード

**会話モード**は、エージェントの自律性を制御します。<kbd>Shift</kbd>+<kbd>Tab</kbd> を押して、モードを切り替えます。

- **Interactive**: ユーザーとエージェントが共同で作業します。エージェントは変更を提案し、続行前に入力を待ちます。
- **Plan**: エージェントが最初に計画を作成し、プロジェクトファイルを編集できない状態になります。
- **Autopilot**: エージェントが自律的に作業し、コードを書き、テストを実行して、タスクが完了するまで反復します。

Plan モードで開始し、計画をレビューしてから、Autopilot で実装します。

## Issue から開始する

フィルター機能の作業を始める前に、Codespace とターミナルを準備します。

1. Codespace に戻ります。停止している場合は、再起動してから続行します。
2. 星評価の PR がマージされていることを確認します。
3. ターミナルが開いていない場合は、<kbd>Control</kbd>+<kbd>`</kbd> (Mac) または <kbd>Ctrl</kbd>+<kbd>`</kbd> (Windows/Linux) を押します。
4. `main` を更新してから、フィルター機能用のブランチを作成します。

   ```bash
   git checkout main
   git pull --ff-only
   git checkout -b game-filters-cli
   ```

5. Copilot CLI を起動します。

   ```bash
   copilot --yolo
   ```

6. <kbd>Tab</kbd> を2回押して **Issues** タブを開きます。
7. <kbd>A</kbd> を押してすべての Issue を表示します。
8. 矢印キーを使って、**Allow users to filter games by category and publisher** というタイトルの Issue を選択します。
9. <kbd>C</kbd> を押してプロンプトに Issue を追加し、**Session** タブに戻ります。

プロンプトが `#7` のような番号で始まっていることを確認してください。`#` を使うと、GitHub 上の Issue やプルリクエスト (PR) をコンテキストに追加できます。

## フィルター機能を計画する

計画を立てることで、機能の実装やタスクの実行方法を Copilot に任せる前に、アプローチを定められます。複雑な作業は、少し時間をかけて計画することをお勧めします。Plan モードに切り替え、Copilot に計画を作成してもらいましょう。

1. <kbd>Shift</kbd>+<kbd>Tab</kbd> を押して Plan モードに切り替えます。プロンプトの下にあるモード表示が **Plan** であることを確認します。
2. 前の手順で追加した Issue の参照の後に、次のプロンプトを入力します。

   ```plaintext
   Create a plan for implementing this feature.
   ```

Copilot は計画を立て始めます。まずプロジェクトを調べて、最適な方法を検討します。

3. フィルター機能の動作方法について Copilot から質問されることがあります。希望に基づいて回答してください。正解は1つではありません。
4. 計画が完成したら、<kbd>Control</kbd>+<kbd>E</kbd> (Mac) または <kbd>Ctrl</kbd>+<kbd>E</kbd> (Windows/Linux) を押して計画を展開します。
5. 上下にスクロールして計画をレビューします。
6. 決めた内容と異なる部分があれば、Copilot に修正を依頼します。

## Autopilot を承認する

計画の作成とレビューが終わったら、実装に進みます。Autopilot モードを使って Copilot に作業を任せます。

Autopilot モードでは、Copilot がタスクを完了したと判断するまで問題に取り組みます。

1. **Accept plan and build on autopilot (recommended)**、またはインストール済みのバージョンに表示される同様の選択肢を選択します。
2. プロンプトの下にあるモード表示が **Autopilot** であることを確認します。
3. Copilot が計画に沿って反復し、コードを生成してテストを実行する様子を確認します。

> [!NOTE]
> 承認するとすぐに実装が始まる場合があるため、先に計画をレビューしてください。依存関係が不足している場合やポートが競合している場合は、セットアップの問題を解決してから、チェックの完了を判断します。

## 実装をレビューして検証する

生成されたコードも、他のコードと同じようにマージ前にレビューしてください。コードをレビューし、サイトを実行して問題がないことを確認します。

1. <kbd>Shift</kbd>+<kbd>Tab</kbd> を押して Interactive モードに切り替えます。モード表示に **Plan** または **Autopilot** が表示されていないことを確認します。
2. `/diff` を入力し、フィルター機能の実装とテストを確認します。
3. 結果を Issue と計画時に決めた内容に照らし合わせます。
4. コードをレビューしたら、<kbd>Esc</kbd> を押して差分画面を閉じます。
5. プロジェクトのチェック結果を確認し、失敗があれば Copilot に修正を依頼します。

## 新機能を確認する

コードに問題がないように見えても、実際に動くでしょうか。前と同じようにアプリを起動し、Codespaces でポート転送されたサイトをブラウザーで開きましょう。

1. 次のプロンプトで、アプリの起動を Copilot に依頼します。

   ```plaintext
   Start the app so I can try the filtering feature in my browser. Tell me the URL and leave the server running.
   ```

2. Codespaces からポート `4321` が利用可能であると通知されたら、**Open in Browser** を選択します。
3. カテゴリによるフィルター、publisher によるフィルター、計画時に合意した組み合わせを試します。
4. リセットと該当結果がない場合の動作が、Issue と決定事項に合っていることを確認します。
5. Codespace に戻り、Copilot が起動した開発サーバーを停止するよう依頼します。

## まとめと次のステップ

複数の会話モードを使って機能を構築し、レビューしました。このレッスンでは、次の作業を行いました。

- GitHub Issue から新しい Copilot の会話を開始しました。
- Plan モードで要件を定義しました。
- Autopilot モードで新機能を実装しました。
- コードをレビューしました。
- 転送されたブラウザーで機能を手動で検証しました。
